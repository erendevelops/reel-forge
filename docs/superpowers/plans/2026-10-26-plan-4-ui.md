# Plan 4 — UI: from option cards to review — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Plan 2 app shell into the full project flow:
- option cards before anything runs;
- transcript check (reels);
- music pick;
- the storyboard workspace with a live preview and direct edits;
- Review with QA results, version compare and feedback;
- learned preferences in Settings.

**Architecture:** A pure `projectStage()` decides which screen a project is on, from `project.json`, the analysis files and the versions; the project page routes on it.
- **Edits:** direct edits are pure functions on `Plan` (lib/app/edits.ts). Saving one creates a user version whose origin records the diff.
- **Preview:** the live preview compiles the (possibly unsaved) plan with the existing compiler into `<project>/.preview/<ratio>/`, adds a small player script that seeks the GSAP timeline and syncs the media elements, and serves the result through a same-origin route into an `<iframe>`.
- **Claude:** everything Claude does still goes through the existing jobs and prompts.

**Tech Stack:** Next.js 15 (app router), React 19, Tailwind 4, zod, vitest + Testing Library + jsdom. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-ai-video-editor-design.md` (§3, §6, §8, §9, §11, §12). Approved mockup: `docs/superpowers/specs/mockups/storyboard-and-option-cards.html`. Plan 3 acceptance: `docs/superpowers/plans/2026-10-25-plan-3-acceptance.md`.

## Global Constraints

- **Theme:** erens.website light theme only. Background `#F7FBF9` (no dot pattern), ink `#111827`, muted `#6B7280`, lines `#E8ECEA`, brand `#3ECF8E` / dark `#1F9D6E`, green top bar.
- **Type:** Silkscreen for headings, JetBrains Mono for labels/buttons/meta, Nunito for body. White cards, 14–18 px radius.
- **Not wanted:** dark mode, dot backgrounds, macOS window buttons, crowded cards.
- **Airy:** one line per scene, small icons instead of tag soup; details (Claude's reason, actions) only on the selected scene.
- **Option cards:** small fixed-size tiles, **six per row** (132 px wide, 84 px preview), a looping animated preview and a short name; the one-line description shows on hover.
- **Claude uses only what is ticked.** The app validates every plan (Claude's or the user's) against the project's selection.
- **Music:** optional. When ticked, the user picks from Claude's suggestions or uploads their own track. Claude never picks silently.
- **Direct edits** need no Claude and produce a version with `by: "user"` and the diff. The diffs of user versions since Claude's last run go into Claude's next run (already in `buildPrompt`).
- **App-video hand editing** covers text, numbers, colours, timings and audio. Animation changes go through Claude.
- **Render is explicit** ("Approve & render"); it renders the final profile for every selected ratio.
- **Languages:** TR/EN for every string (`lib/i18n/{tr,en}.ts`, key parity is tested). Claude replies in the project language.
- **Long runs** show the live step list (the existing `JobLog`), never a frozen spinner.
- **Local only:** every API route stays behind the existing request guard (loopback host, same-origin). File routes never serve outside the project folder.

## Review Focus

1. **A job is already running** when the user clicks render, confirm cards, analyse or ask Claude. Expect a visible message ("a job is already running"), no crash and no second job. Task 1 owns the shared `postJob` helper and its test.
2. **A transcript word edited into two words or emptied.** Timings must never move. A chip may hold spaces, the word count never changes, and an empty word is refused with 400. Task 4.
3. **Editing an older version while a newer one exists** (Claude saved v3 while the user edits v2). The save becomes v4 with `parent: 2`, and the UI says it was branched from v2. Task 8.
4. **Seeking in large videos** in the preview and Review. File routes answer `Range` with 206, the right `Content-Range` and a byte-exact length, and refuse `..`, absolute paths and encoded traversal, including the non-ASCII `Masaüstü` project path. Task 6.
5. **Uploading a music file** that isn't audio, is huge, or has an odd name (Turkish characters, spaces, `../x.mp3`). Only `.mp3/.wav/.m4a/.ogg/.flac` up to 50 MB is accepted, saved under a sanitised name in `inputs/music/`. Task 5.
